# QA Testing Templates Folder

This folder contains reusable templates for QA documentation and test artifacts.

## Available Templates

### 1. Bug Report Template
**File:** `bug_report_template.md`

**Purpose:** Standardized format for reporting defects

**Key Sections:**
- Bug ID and metadata
- Summary and description
- Environment details
- Steps to reproduce
- Expected vs. Actual results
- Screenshots and logs
- Severity and priority assessment

**When to Use:**
- When a defect is discovered during testing
- Communicating issues to development team
- Tracking and managing bug lifecycle

---

### 2. Test Case Template
**File:** `test_case_template.md`

**Purpose:** Standardized format for creating test cases

**Key Sections:**
- Test case identification
- Description and purpose
- Pre-conditions
- Test data specifications
- Step-by-step test instructions
- Expected results
- Post-conditions
- Pass/Fail criteria

**When to Use:**
- Creating new test cases
- Documenting manual test procedures
- Ensuring consistency across test suite

---

## How to Use Templates

### Option 1: Copy and Fill
1. Open the template file
2. Copy all content
3. Create new file with specific name (e.g., `TC-001_signup_valid.md`)
4. Replace placeholders with actual content
5. Remove/modify sections as needed

### Option 2: Template as Guide
1. Use template as reference for structure
2. Create document with appropriate content
3. Follow template's sections and best practices
4. Adapt sections for your specific needs

---

## Template Customization

### For Bug Reports
- Adjust severity levels based on your scale
- Add custom fields for your workflow
- Include your specific product information
- Modify QA sign-off section for your team

### For Test Cases
- Adjust TC-ID format to match your naming convention
- Modify module/feature names for your app
- Add custom fields for your testing process
- Adjust table structures for clarity

---

## Best Practices

✅ **DO:**
- Use templates consistently across QA team
- Customize templates for your specific needs
- Review and update templates regularly
- Share templates with new team members
- Keep templates version-controlled

❌ **DON'T:**
- Leave template placeholders unfilled
- Skip important sections
- Use inconsistent terminology
- Create conflicting local versions
- Ignore feedback on template improvements
